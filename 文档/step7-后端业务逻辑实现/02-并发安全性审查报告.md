## 一、🔴 严重问题：抢单未使用乐观锁

### 1.1 问题代码（TaskServiceImpl.acceptTask）

```java
@Override
@Transactional
public boolean acceptTask(Long taskId, Long helperId) {
    Task task = taskMapper.selectById(taskId);
    if (task == null) throw BusinessException.notFound("任务不存在");
    if (!"pending".equals(task.getStatus())) {
        throw BusinessException.conflict("任务状态不允许接单");
    }
    if (task.getRequesterId().equals(helperId)) {
        throw BusinessException.badRequest("不能接自己发布的任务");
    }

    task.setHelperId(helperId);
    task.setStatus("ongoing");
    // ⚠️ 问题：没有 WHERE version=? 条件
    int updated = taskMapper.updateById(task);
    if (updated == 0) {
        throw BusinessException.conflict("任务已被其他人接单");
    }
    // ...
}
```

### 1.2 问题分析

**时序图（10 个用户同时抢单 task_id=1）**：

```
T0 时刻：task = {id:1, status:pending, helper_id:null, version:0}

T1: User A 调 acceptTask
    SELECT * FROM task WHERE id=1  → {status:pending, version:0}
    业务校验通过
    UPDATE task SET status='ongoing', helper_id=A, version=1 WHERE id=1
    (MySQL 没有 WHERE version=0 条件)
    
T1 同一时刻: User B 也调 acceptTask
    SELECT * FROM task WHERE id=1  → {status:pending, version:0}  ← 还没看到 A 的更新
    业务校验通过
    UPDATE task SET status='ongoing', helper_id=B, version=1 WHERE id=1
    (覆盖了 A 的设置!)
    
T2: 任务表实际状态 = {status:'ongoing', helper_id:B, version:1}
    A 不知道自己的接单"成功"了（因为 updateById 返回 1）
    系统记录 B 是接单方，但 A 也以为自己是
    → 出现"两个接单方"的脏数据
```

### 1.3 修复方案：MyBatis-Plus 乐观锁

#### 方案 A：使用 MyBatis-Plus 的 `@Version` 注解（推荐）

**Step 1：Mapper 层**

```java
// TaskMapper.java
@Update("UPDATE task SET helper_id = #{helperId}, status = #{status}, " +
        "version = version + 1 " +
        "WHERE id = #{id} AND version = #{version} AND status = 'pending'")
int updateTaskWithVersion(@Param("id") Long id,
                          @Param("helperId") Long helperId,
                          @Param("status") String status,
                          @Param("version") Integer version);
```

**Step 2：Service 层**

```java
@Override
@Transactional
public boolean acceptTask(Long taskId, Long helperId) {
    Task task = taskMapper.selectById(taskId);
    if (task == null) throw BusinessException.notFound("任务不存在");
    if (!"pending".equals(task.getStatus())) {
        throw BusinessException.conflict("任务状态不允许接单");
    }
    if (task.getRequesterId().equals(helperId)) {
        throw BusinessException.badRequest("不能接自己发布的任务");
    }

    // ✅ 用乐观锁更新
    int updated = taskMapper.updateTaskWithVersion(
        taskId, helperId, "ongoing", task.getVersion()
    );
    if (updated == 0) {
        // 说明 version 已经被别人改了（被别人抢走了）
        throw BusinessException.conflict("任务已被其他人接单");
    }
    // ... 后续业务逻辑
}
```

**Step 3：并发场景下的正确行为**

```
T0: task = {id:1, status:pending, version:0}

T1: User A 调 acceptTask
    SELECT * FROM task WHERE id=1  → {version:0}
    UPDATE ... WHERE id=1 AND version=0  → 影响 1 行 ✅
    现在 task = {version:1, helper_id:A}

T1 同一时刻: User B 调 acceptTask
    SELECT * FROM task WHERE id=1  → {version:0} ← 还没看到 A 的更新
    UPDATE ... WHERE id=1 AND version=0  → 影响 0 行 ❌
    updated == 0，抛 409 异常
    B 收到"任务已被其他人接单"提示 ✅
```

## 二、🟠 中等问题 1：转账未使用乐观锁

### 2.1 问题代码（AccountServiceImpl.transfer）

```java
@Override
@Transactional
public void transfer(Long fromUserId, Long toUserId, BigDecimal amount, Long taskId) {
    Account fromAccount = getAccount(fromUserId);
    if (fromAccount.getFrozenBalance().compareTo(amount) < 0) {
        throw BusinessException.badRequest("冻结金额不足");
    }
    Account toAccount = getAccount(toUserId);

    BigDecimal serviceFee = amount.multiply(new BigDecimal("0.05"));
    BigDecimal actualAmount = amount.subtract(serviceFee);

    fromAccount.setFrozenBalance(fromAccount.getFrozenBalance().subtract(amount));
    BigDecimal toBeforeBalance = toAccount.getBalance();
    toAccount.setBalance(toAccount.getBalance().add(actualAmount));

    accountMapper.updateById(fromAccount);
    accountMapper.updateById(toAccount);
    // ⚠️ 问题：并发场景下 fromAccount 可能已被其他事务修改
}
```

### 2.2 风险

- 用户同时**接单 + 提现**时，可能出现余额扣成负数
- 用户同时**被两个任务结算**时，账户余额可能重复加钱

### 2.3 修复方案

```java
// AccountMapper.java 新增
@Update("UPDATE account SET frozen_balance = frozen_balance - #{amount}, " +
        "version = version + 1 " +
        "WHERE user_id = #{userId} AND version = #{version} " +
        "AND frozen_balance >= #{amount}")
int deductFrozenWithVersion(@Param("userId") Long userId,
                            @Param("amount") BigDecimal amount,
                            @Param("version") Integer version);

@Update("UPDATE account SET balance = balance + #{amount}, " +
        "version = version + 1 " +
        "WHERE user_id = #{userId} AND version = #{version}")
int addBalanceWithVersion(@Param("userId") Long userId,
                          @Param("amount") BigDecimal amount,
                          @Param("version") Integer version);
```

```java
// AccountServiceImpl.java
public void transfer(Long fromUserId, Long toUserId, BigDecimal amount, Long taskId) {
    Account fromAccount = getAccount(fromUserId);
    if (fromAccount.getFrozenBalance().compareTo(amount) < 0) {
        throw BusinessException.badRequest("冻结金额不足");
    }
    int updated = accountMapper.deductFrozenWithVersion(
        fromUserId, amount, fromAccount.getVersion()
    );
    if (updated == 0) {
        throw BusinessException.conflict("账户余额变动，请重试");
    }
    
    Account toAccount = getAccount(toUserId);
    int updated2 = accountMapper.addBalanceWithVersion(
        toUserId, amount.subtract(serviceFee), toAccount.getVersion()
    );
    if (updated2 == 0) {
        throw BusinessException.conflict("对方账户变动，请重试");
    }
    // ... 流水记录
}
```

## 三、🟠 中等问题 2：验收未使用乐观锁

### 3.1 问题代码（TaskServiceImpl.completeTask）

```java
public boolean completeTask(Long taskId, Long requesterId) {
    Task task = taskMapper.selectById(taskId);
    if (!"pending_review".equals(task.getStatus())) {
        throw BusinessException.conflict("任务状态不允许验收");
    }
    accountService.transfer(...);
    task.setStatus("completed");
    taskMapper.updateById(task);  // ⚠️ 没有 version 校验
    // ...
}
```

### 3.2 风险

- 需求方和管理员**同时点验收**时，可能触发两次 `transfer`
- 资金**双倍**进入接单方账户

### 3.3 修复方案

```java
@Update("UPDATE task SET status = 'completed', " +
        "version = version + 1 " +
        "WHERE id = #{id} AND version = #{version} AND status = 'pending_review'")
int completeTaskWithVersion(@Param("id") Long id, @Param("version") Integer version);
```

```java
public boolean completeTask(Long taskId, Long requesterId) {
    Task task = taskMapper.selectById(taskId);
    if (task == null || !"pending_review".equals(task.getStatus())) {
        throw BusinessException.conflict("任务状态不允许验收");
    }
    
    // 先尝试更新状态
    int updated = taskMapper.completeTaskWithVersion(taskId, task.getVersion());
    if (updated == 0) {
        throw BusinessException.conflict("任务已被其他操作修改，请重试");
    }
    
    // 状态更新成功后再转账
    accountService.transfer(task.getRequesterId(), task.getHelperId(), 
                            task.getReward(), taskId);
    // ...
}
```

> ⚠️ **重要**：**先改状态再转账**，而非先转账再改状态。理由：状态改失败 = 没人竞争；状态改成功 = 拿到锁，再转账。

## 四、🟡 轻微问题：dispute/cancel/rate 也类似

`disputeTask` / `cancelTask` / `rateTask` 都有同样的 `if + updateById` 模式，建议**统一优化**。

| 方法 | 状态变更 | 优化优先级 |
|------|---------|----------|
| `acceptTask` | pending → ongoing | 🔴 P0（已修） |
| `submitTask` | ongoing → pending_review | 🟠 P1 |
| `completeTask` | pending_review → completed | 🟠 P1（已给出方案） |
| `cancelTask` | pending → cancelled | 🟠 P1 |
| `disputeTask` | * → disputed | 🟡 P2 |
| `rateTask` | completed → completed | 🟢 P3（只插 review 表） |

## 五、测试方案

### 5.1 并发抢单测试（JUnit 5 + ExecutorService）

```java
@SpringBootTest
public class TaskConcurrencyTest {

    @Autowired private TaskService taskService;
    @Autowired private TaskMapper taskMapper;

    @Test
    void testConcurrentAccept_OnlyOneSucceeds() throws Exception {
        // 准备：1 个待接单任务
        Long taskId = createPendingTask();  // helper
        int threadCount = 10;

        ExecutorService executor = Executors.newFixedThreadPool(threadCount);
        CountDownLatch latch = new CountDownLatch(1);
        AtomicInteger successCount = new AtomicInteger(0);
        AtomicInteger conflictCount = new AtomicInteger(0);

        List<Future<?>> futures = new ArrayList<>();
        for (int i = 0; i < threadCount; i++) {
            final long helperId = 100L + i;  // 10 个不同 helper
            futures.add(executor.submit(() -> {
                try {
                    latch.await();  // 所有线程同时启动
                    taskService.acceptTask(taskId, helperId);
                    successCount.incrementAndGet();
                } catch (BusinessException e) {
                    if (e.getCode() == 409) conflictCount.incrementAndGet();
                    else throw e;
                }
            }));
        }

        latch.countDown();  // 同时释放
        for (Future<?> f : futures) f.get(10, TimeUnit.SECONDS);
        executor.shutdown();

        // 断言：只有 1 个成功，9 个 409
        assertEquals(1, successCount.get(), "只有 1 个接单成功");
        assertEquals(9, conflictCount.get(), "其他 9 个都应收到 409 冲突");
        
        // 数据库中只有 1 个 helper_id
        Task finalTask = taskMapper.selectById(taskId);
        assertEquals("ongoing", finalTask.getStatus());
        assertNotNull(finalTask.getHelperId());
    }
}
```
