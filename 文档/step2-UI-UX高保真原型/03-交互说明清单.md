## 一、任务大厅（Home.vue）

> 路径 `/home`，登录后默认入口；需求方/接单方/管理员均可访问。

### 1.1 页面结构

```
┌─────────────────────────────────────────────────┐
│ 顶部 Hero 区（标题 + 发布任务按钮）               │
├─────────────────────────────────────────────────┤
│ 搜索框（标题/描述） + 分类筛选条（4 个胶囊）      │
├─────────────────────────────────────────────────┤
│ 数据卡片三联：任务总数 / 可接任务 / 当前筛选        │
├─────────────────────────────────────────────────┤
│ 任务列表（卡片网格，2 列）                         │
│  - 卡片右上：状态标签（StatusTag）                │
│  - 卡片右下：浏览数                               │
│  - 整卡可点击 → 跳转 /task/:id                    │
├─────────────────────────────────────────────────┤
│ 空数据：插画 + 提示文案                            │
└─────────────────────────────────────────────────┘
```

### 1.2 关键交互

| 触发对象 | 事件 | 反馈 |
|---------|------|------|
| 顶部"发布任务"按钮 | click | 跳 `/publish`（仅 requester/admin 可见） |
| 搜索框 input | input | `searchQuery` 实时绑定，触发 `filteredTasks` 计算属性 |
| 分类胶囊（4 个） | click | 切换 `selectedCategory`，胶囊背景色变为 `var(--role-accent)` |
| 任务卡片 | click | 调 `taskApi.getDetail(id)`，跳 `/task/:id` |
| 加载中 | 自动 | 4 个骨架屏 `animate-pulse` 动画 |
| 空筛选结果 | 自动 | 展示插画 + "暂无符合条件的任务" 提示 |

### 1.3 角色相关差异

- **helper 视角**：Hero 文案变"任务广场"（"筛选合适的校园任务，接单后按流程提交完成"）
- **requester 视角**：Hero 文案为"任务大厅"（"查看校园互助任务，需求方可以快速发布新的委托"）
- **admin 视角**：同 helper（看任务为主）

### 1.4 API 调用

| 调用 | 触发 | 失败处理 |
|------|------|---------|
| `taskApi.getList()` | `onMounted(loadTasks)` | `console.error` 打印，无 UI 提示（待改进） |

## 二、任务详情（TaskDetail.vue）

> 路径 `/task/:id`，任务全状态机的"中枢页面"——按钮根据状态/角色条件渲染。

### 2.1 页面结构

```
┌─────────────────────────────────────────────────┐
│ 返回按钮 ← router.back()                          │
├──────────────────────────┬──────────────────────┤
│ 左侧主区（2/3 宽）        │ 右侧操作区（1/3 宽）  │
│  ┌──────────────────────┐│ 任务信息卡片         │
│  │ 任务标题 + 状态 + 金额 ││ - 编号/时间/截止/浏览│
│  │ 任务描述（白底卡片）   │├──────────────────────┤
│  │ 地点 / 联系方式        ││ 操作按钮（按条件渲染）│
│  ├──────────────────────┤│  - 立即接单          │
│  │ 对方信息卡片          ││  - 提交完成          │
│  │ 头像 + 用户名 + 手机号 ││  - 验收任务          │
│  └──────────────────────┘│  - 评价对方          │
│                          ├──────────────────────┤
│                          │ 黄色提示卡片          │
│                          │ "等待验收中"（当       │
│                          │ 你是接单方时显示）     │
└──────────────────────────┴──────────────────────┘
```

### 2.2 关键交互（**状态机最复杂的页面**）

| 触发对象 | 事件 | 反馈 |
|---------|------|------|
| 返回按钮 | click | `router.back()` 回上一页 |
| **操作按钮条件渲染** | - | 详见下表 ⚠️ |

#### 2.2.1 4 个操作按钮的条件矩阵

| 按钮 | 渲染条件 | 点击行为 |
|------|---------|---------|
| 立即接单 | `status==pending` AND `role==helper` AND `requesterId != userId` | 调 `taskApi.accept({taskId, userId})` → 成功 `alert('接单成功')` + 跳 `/my-tasks` |
| 提交完成 | `status==ongoing` AND `helperId == userId` | 跳 `/submit/:id` |
| 验收任务 | `status==pending_review` AND `requesterId == userId` | 跳 `/review/:id` |
| 评价对方 | `status==completed` | 跳 `/rate/:id` |

#### 2.2.2 等待验收提示卡片

- 渲染条件：`status==pending_review` AND `requesterId != userId`（即你是接单方）
- 内容：黄色背景 + 钟表图标 + "需求方正在验收您提交的任务"
- 无交互，纯提示

### 2.3 加载/错误状态

| 状态 | UI 表现 |
|------|--------|
| 加载中 | 居中旋转 loading 图标 |
| 任务不存在 | "任务不存在" 文案 |
| 正常 | 主内容区 |

### 2.4 已知问题（PRD §7.2 已记录）

- 接单成功后**无乐观锁保护**（Step 7 必修）
- 接单 API 调用**未传 userId**（代码 `taskApi.accept({taskId, userId})` 但后端从 JWT 解析）——属于"客户端冗余"，不影响功能

## 三、发布任务（Publish.vue）

> 路径 `/publish`，仅 `requester` / `admin` 可访问。

### 3.1 页面结构

```
┌─────────────────────────────────────────────────┐
│ 标题区："发布任务" + 副标题                       │
├─────────────────────────────────────────────────┤
│ 表单卡片                                         │
│  - 任务标题（input，maxlength=50）               │
│  - 任务分类（4 个胶囊按钮，选中变 accent-mauve）│
│  - 任务描述（textarea，rows=5）                  │
│  - 任务地点（input）                             │
│  - 联系方式（input）                             │
│  - 截止时间（datetime-local）                    │
│  - 任务报酬（number，min=0，step=0.01）         │
│  - 金额预览卡片（实时计算服务费、合计）           │
│  - [取消] [发布任务] 按钮组                      │
└─────────────────────────────────────────────────┘
```

### 3.2 关键交互

| 触发对象 | 事件 | 反馈 |
|---------|------|------|
| 任务标题 input | input | 实时绑定；显示 "X/50" 字符计数 |
| 任务分类胶囊 | click | 切换 `form.category`；视觉切换为 accent-mauve 背景 |
| 任务描述 textarea | input | 实时绑定 |
| 任务报酬 input | input | 触发 `serviceFee` / `totalFee` 计算属性 |
| 金额预览卡片 | 自动 | 实时显示 报酬 ¥X / 服务费 ¥X / 合计 ¥X |
| **取消按钮** | click | `router.back()` 返回 |
| **发布按钮** | click | 调 `validate()` 校验 → 通过则调 `taskApi.publish()` → 成功 `alert('任务发布成功')` + 跳 `/my-tasks` |

### 3.3 表单校验（前端 validate 函数）

| 字段 | 校验规则 | 错误提示 |
|------|---------|---------|
| 标题 | 非空 trim | "请输入任务标题" |
| 描述 | 非空 trim | "请输入任务描述" |
| 分类 | 已选 | "请选择任务分类" |
| 截止时间 | 非空 | "请选择截止时间" |
| 报酬 | > 0 | "请输入有效的报酬金额" |

### 3.4 实时金额计算

| 输入 | 计算 |
|------|------|
| 报酬 R | 服务费 = R × 0.05 |
| 报酬 R + 服务费 | 合计 = R × 1.05（**实际冻结只看 R，5% 是验收时才扣**——见 PRD §6.2） |

> ⚠️ **注**：前端显示"合计"会包含服务费，但实际后端冻结时**只冻结 R**。这是 PRD §6.1 的设计：服务费不在发布时预扣。此处有**轻微文档-UI 偏差**，但不影响核心业务（不实际扣用户的钱）。

### 3.5 API 调用

| 调用 | 触发 | 失败处理 |
|------|------|---------|
| `taskApi.publish({...})` | 点"发布" | `console.error` + `alert('发布任务失败')` |

## 四、我的任务（MyTasks.vue）

> 路径 `/my-tasks`，登录即可访问。根据角色显示不同 tab。

### 4.1 页面结构

```
┌─────────────────────────────────────────────────┐
│ Hero 区（标题 + 副标题）                          │
│  - helper："我的接单"                            │
│  - requester/admin："我的任务"                   │
├─────────────────────────────────────────────────┤
│ Tab 栏（按角色不同）                              │
│  - helper：1 个 tab "我接收的"                   │
│  - requester：1 个 tab "我发起的"                │
│  - admin：2 个 tab "我发起的" + "我接收的"       │
├─────────────────────────────────────────────────┤
│ 状态过滤条（6 个状态胶囊：全部/待接单/...）       │
├─────────────────────────────────────────────────┤
│ 任务列表                                         │
│  - 每行：标题 + 状态 + 描述 + 截止 + 金额 + 操作  │
│  - 整行可点击 → /task/:id                        │
│  - 行右侧操作按钮（按 status × tab 条件渲染）     │
├─────────────────────────────────────────────────┤
│ 空数据：插画 + 文案 + 行动按钮                    │
└─────────────────────────────────────────────────┘
```

### 4.2 关键交互

| 触发对象 | 事件 | 反馈 |
|---------|------|------|
| Tab 切换 | click | 切换 `activeTab`，tab 底部出现下划线 |
| 状态过滤胶囊 | click | 切换 `filterStatus`，筛选 currentTasks |
| 任务行 | click | 跳 `/task/:id` |
| 行内操作按钮 | click（**stop 阻止冒泡**） | 详见下表 |
| 取消按钮 | click | `confirm()` 弹窗 → 调 `taskApi.cancel({taskId})` → 重新 loadTasks |
| 空数据"去任务广场看看"按钮 | click | 跳 `/home` |
| 空数据"发布任务"按钮 | click | 跳 `/publish` |

### 4.3 行内操作按钮矩阵

| 所属 tab | 任务 status | 按钮 | 点击行为 |
|---------|------------|------|---------|
| published（我发起的） | pending_review | 去验收 | 跳 `/review/:id` |
| published | completed | 评价对方 | 跳 `/rate/:id` |
| published | pending | 取消（红色） | confirm + cancel API |
| accepted（我接收的） | ongoing | 提交完成 | 跳 `/submit/:id` |
| accepted | pending_review | 等待验收（禁用） | - |
| accepted | completed | 评价对方 | 跳 `/rate/:id` |

### 4.4 API 调用

| 调用 | 触发 |
|------|------|
| `taskApi.getMyTasks(userId, 'published')` | onMounted |
| `taskApi.getMyTasks(userId, 'accepted')` | onMounted |
| `taskApi.cancel({taskId})` | 点"取消"按钮 |

## 五、管理后台（Admin.vue）

> 路径 `/admin`，**仅 admin** 可访问。Vue Router 守卫 + 后端 `@RequiresRoles({"admin"})` 双层保护。

### 5.1 页面结构

```
┌─────────────────────────────────────────────────┐
│ Hero 区：管理员后台 + 4 个 tab                   │
│  - 平台监控                                      │
│  - 违规任务审核（显示待审核数）                   │
│  - 用户申诉处理（显示争议数）                     │
│  - 用户风控（显示正常用户数）                     │
├─────────────────────────────────────────────────┤
│ Tab 1: 平台监控                                   │
│  - 4 个数据卡片（待接单/已完成/争议中/待审核）    │
│  - 4 个进度条（最大值的归一化柱状）               │
│  - 平台总交易额卡片                              │
├─────────────────────────────────────────────────┤
│ Tab 2: 违规任务审核                               │
│  - 任务列表（仅 status=pending 审核）            │
│  - 行操作：[通过] [下架]                         │
├─────────────────────────────────────────────────┤
│ Tab 3: 用户申诉处理                               │
│  - 争议任务列表                                  │
│  - 行操作：[支持需求方] [支持接单方]              │
├─────────────────────────────────────────────────┤
│ Tab 4: 用户风控                                   │
│  - 用户列表（手机号/角色/信用分/状态）            │
│  - 行操作：[冻结]                                 │
└─────────────────────────────────────────────────┘
```

### 5.2 关键交互

| 触发对象 | 事件 | 反馈 |
|---------|------|------|
| Tab 切换 | click | 切换 `activeTab` |
| **审核通过按钮** | click | 调 `adminApi.approveTask(taskId, {remark})` → 从 auditTasks 移除该项 + 重新 loadData |
| **下架任务按钮** | click | `window.prompt('请输入下架原因')` → 调 `adminApi.takeDownTask(taskId, {reason})` |
| **争议处理按钮** | click | 调 `adminApi.resolveDispute(taskId, {result, remark})` |
| **冻结用户按钮** | click | `confirm()` 弹窗 → 调 `adminApi.freezeUser(userId)` |

### 5.3 数据加载策略

- **首次加载**：`Promise.all([stats, audit, tasks, disputes, users])` 并行 5 个请求
- **单操作后**：先乐观更新本地数组（filter 掉已处理项），再调 `loadData()` 重新拉数据
- **失败处理**：`alert(error.response?.data?.message || '默认错误')`

### 5.4 已知 UI 缺陷

- 4 个 tab 同时渲染（用 `v-if` 控制显示，但 DOM 全加载）——性能 OK 但 DOM 量大
- 列表分页未做（只 `pageSize: 50`）——管理员场景数据量小，可接受

## 六、5 页面的共同设计原则

### 6.1 一致的视觉锚点

- **状态标签**：所有页面的 `StatusTag` 颜色映射一致（pending=蓝/ongoing=橙/pending_review=黄/completed=绿/disputed=红/cancelled=灰）
- **金额显示**：所有页面金额用 `Number(task.reward || 0).toFixed(2)` 统一格式
- **日期显示**：`toLocaleDateString('zh-CN', {month: 'short', day: 'numeric'})` 短日期
- **加载态**：骨架屏 + 旋转图标 + Empty 三选一

### 6.2 一致的错误处理

- 所有 API 失败都用 `alert()` 弹出 `error.response?.data?.message`
- 改进建议（未做）：用全局 toast/notification 组件替代 alert
- 改进建议（未做）：4xx 错误区分"用户错误"（如余额不足）和"系统错误"（如 500）

### 6.3 一致的导航

- 顶部 Navbar 全局可见
- Logo 点击回 `/home`
- 用户头像点击回 `/profile`
- "我的任务" 全角色可见
- "管理后台" 仅 admin 可见
- "发布任务" 仅 requester/admin 可见
