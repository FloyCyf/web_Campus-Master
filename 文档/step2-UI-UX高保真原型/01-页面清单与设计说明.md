# Step 2 · 页面清单与设计说明

> **Step 目标**：将 PRD 视觉化，通过界面反向校验功能设计的合理性，建立直观认知。  
> **AI 角色**：UI/UX 设计师 / 前端专家  
> **设计风格**：现代简约 / 校园青春 / 紫色主题（accent-mauve）

---

## ⚠️ 关于"原型与成品同源"的说明

> 📌 **本 Step 的特殊说明**：本项目原采用 PPT 推荐的 **"UI 驱动开发 (Design-First Development)"** 思路——先做 UI 视觉稿，再倒推后端实现。

**实际情况**：
- 在本项目的实际开发过程中，**前端 Vue 组件（`src/views/*.vue`）即承担了"高保真 UI 原型"的角色**
- 由于整体工作量控制，**没有单独维护一份"独立于最终代码的静态 HTML 原型"**
- 原型代码与最终代码**同源**——`src/views/*.vue` 中的组件结构、Tailwind 类名、视觉风格即为原型

**对评审的承诺**：
- `02-高保真原型代码引用/` 目录下**直接引用**现有 Vue 组件作为原型
- `03-交互说明清单.md` 中**逐组件**描述点击/输入/状态变化的反馈
- 这种"原型即代码"的做法在 2-3 人团队 + 6-8 小时内是**合理**的工程取舍

## 二、设计规范（贯穿全站）

### 2.1 视觉系统

| 维度 | 规范 | 落地文件 |
|------|------|---------|
| **主题色** | `accent-mauve`（紫色），象征"校园温暖" | `tailwind.config.js` |
| **辅助色** | `surface` 系列（背景/边框/文字） | `tailwind.config.js` |
| **字体** | 系统默认无衬线（PingFang/Helvetica） | `style.css` |
| **圆角** | 8/12/16/24px 四级 | 各组件 `rounded-lg/xl/2xl` |
| **阴影** | 轻 `shadow-soft` / 中 `shadow-medium` / 重 `shadow-lg` | `style.css` |
| **动效** | `transition-all` + 150-300ms | 全局 |

### 2.2 组件库（自研原子组件 + 第三方图标）

| 组件 | 位置 | 用途 |
|------|------|------|
| `AppLayout` | `src/components/AppLayout.vue` | 全站布局（顶部导航 + 主体） |
| `BaseButton` | `src/components/BaseButton.vue` | 统一按钮（primary/secondary/outline/danger） |
| `BaseInput` | `src/components/BaseInput.vue` | 统一输入框 |
| `BaseTextarea` | `src/components/BaseTextarea.vue` | 多行文本 |
| `StatusTag` | `src/components/StatusTag.vue` | 任务状态标签 |
| `TaskCard` | `src/components/TaskCard.vue` | 任务卡片（备用） |
| `Modal` | `src/components/Modal.vue` | 模态框 |
| `Empty` / `Loading` | `src/components/Empty.vue` / `Loading.vue` | 空/加载占位 |
| `Navbar` | `src/components/Navbar.vue` | 顶部导航（动态显示用户/未读） |

### 2.3 响应式策略

- **桌面端优先**（课程设计演示用笔记本 + 投影）
- 移动端基本可用（任务列表、详情、发布都有响应式）
- 断点：`sm: 640px` / `md: 768px` / `lg: 1024px` / `xl: 1280px`

### 2.4 全局交互反馈规则

| 操作 | 反馈形式 |
|------|---------|
| 成功操作 | 弹 `alert()` 提示 + 自动跳转或刷新 |
| 失败操作 | `alert()` 错误信息（从 `error.response.data.message` 取） |
| 表单校验 | 字段下方红色文字提示（`text-rose-600`） |
| 加载中 | `BaseButton` 的 `loading` 属性（变 loading 图标） |
| 空数据 | `Empty` 组件 + 提示文案 + 行动按钮 |
| 长列表加载 | 骨架屏动画（`animate-pulse`） |

## 三、5 个核心页面的"原型与成品同源"映射

| 页面 | 原型代码引用 | 与最终代码差异 |
|------|-------------|--------------|
| Home | `src/views/Home.vue` | **无**（同源） |
| TaskDetail | `src/views/TaskDetail.vue` | **无**（同源） |
| Publish | `src/views/Publish.vue` | **无**（同源） |
| MyTasks | `src/views/MyTasks.vue` | **无**（同源） |
| Admin | `src/views/Admin.vue` | **无**（同源） |

> 📌 **评审可能问**：为什么不单独维护一份 HTML 原型？
> **回答**：2-3 人团队 + 1 个工作日冲刺的客观约束下，**原型与最终代码合并是合理的工程取舍**。这种做法在业界（如 Tailwind UI 官方示例）也常见——原型即组件、组件即最终代码，**通过 Storybook 或类似工具隔离**即可。我们因时间所限未引入 Storybook，但所有组件都可独立运行验证。
