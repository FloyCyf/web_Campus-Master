## 一、为什么要重做这件事？

### 1.1 课程评分标准（来自 PPT 第 12 页）

| 评分项 | 分值 | 现状评估（自评） |
|--------|------|------------------|
| 一、阶段1完成情况 | 10 分 | ✅ 已完成（树洞项目） |
| 二、阶段2完成情况 | 10 分 | ✅ 已完成（部署上线） |
| 三、阶段3作品内容及质量 | 40 分 | ⚠️ 基本功能 OK，扩展功能、系统方案、UI 还需打磨 |

### 1.2 验收材料（来自 PDF 验收说明）

报告正文第 10 项即为 **"AI 辅助开发实战与方法论沉淀（重点章节）"**——
> "你们团队使用的 AI Coding 工具及 AI 工作模式；核心场景的"人机协作迭代"记录；个人反思"

> ⚠️ **结论**：AI 使用情况是**评分的核心拉开分项**，且必须体现**人工审查作用**而非"一味相信 AI"。

### 1.3 现有项目的问题

通过对 12 份文档和前后端代码的全量阅读，发现：

| 类别 | 已完成 | 缺失/薄弱 |
|------|--------|----------|
| **PRD** | ✅ 有 | 与代码实现已出现偏差（如 `credit_score` 上限 100 vs 150、文档要求"实名认证"但代码无） |
| **UI/UX 原型** | ❌ 无独立原型文档 | 只有最终代码，没有"先做 UI 反推"的迭代痕迹 |
| **API 文档** | ✅ 42KB Markdown | 与 Controller 实际路径不一致（文档写 `/api/v1/`，代码用 `/api/`） |
| **架构设计** | ✅ 有 | 与"AI 协作产出"无关联，看不出 AI 怎么参与 |
| **数据库** | ✅ 完整 schema.sql | 文档与 schema.sql 中字段命名/索引存在差异（如 `frozen_balance` vs `frozen_amount`） |
| **前端 Mock** | ⚠️ 有 mock/index.js | 但 main.js 门控不严，未在文档中说明策略 |
| **后端实现** | ✅ 6 个 Controller 齐备 | 缺 Swagger 落地；缺冒烟测试；缺模块化 SPEC 记录 |
| **集成测试** | ✅ 有测试报告（45 用例全过） | 缺真实跑通的截图/视频佐证 |
| **AI 协作记录** | ❌ **完全没有** | 这是要补齐的核心 |
| **方法论沉淀** | ❌ **完全没有** | 验收重点 |

## 二、路线图（基于 PPT 第 13-38 页原文，**严格按照 PPT 8 步**）

按 PPT 的 8 个 Step 展开。所有 Step 顺序严格遵循"基础设施先行、垂直切片、增量演进"原则。

| Step | 名称 | AI 角色 | 核心产出物 | **人工审查重点** |
|------|------|---------|------------|------------------|
| **1** | 产品定义与 PRD 撰写 | 资深产品经理 | 修订版 PRD、Mermaid 状态机 | 业务规则是否覆盖所有 corner case？MVP 范围是否合理？ |
| **2** | UI/UX 高保真原型设计 | UI/UX 设计师 | 关键页面 HTML/Tailwind 原型 + 截图 | 视觉风格与校园定位匹配？交互路径是否有死路？ |
| **3** | API 接口契约设计 | 后端架构师 | OpenAPI 3.0 / Swagger 文档 | 路径命名、错误码、抢单状态码是否完备？ |
| **4** | 技术选型与系统架构 | 架构师 | 技术栈选型对比表、分层架构图 | 是否过度设计？是否符合 2-3 人团队能力？ |
| **5** | 数据架构与存储建模 | DBA | ER 图 + 完整 DDL + 索引说明 | 字段类型、约束、外键、乐观锁字段是否正确？ |
| **6** | 前端工程化与 Mock 开发 | 前端工程师 | 编码规范、路由、Mock 数据 | Mock 与未来真接口的命名是否一致？ |
| **7** | 后端业务逻辑实现 | 后端工程师 | Controller/Service/Mapper + 单元测试 | 事务边界、并发安全、权限校验是否到位？ |
| **8** | 前后端集成联调与测试 | 全栈工程师 | 联调记录、测试报告、演示视频 | 真接口与契约一致性？跨域/CORS？ |

> 📌 **关于"AI 协作方法论沉淀"**：根据 review 决定，**不单独占一个 Step**，而是**贯穿所有 8 步**，每个 Step 的产出物里都包含"AI 对话记录"和"人工审查清单"两件套。
> 📌 **关于"验收交付材料"**：根据 review 决定，**不单独占一个 Step**，而是在 **Step 8 末尾** 顺带完成"报告整合 + 提交物准备"（约 0.5 天工作量）。
> 📌 **关于 `AI协作记录沉淀/` 文件夹**：脱离路线图独立存在，用于**额外**保存"特别好的 AI 问答"或"能体现个人思考的亮点"，**由 Claude 主动提醒、Floy 决定是否保存**。

## 三、实施计划（按时间分阶段、每步含 AI 使用方式 & 人工审查清单）

> **总周期**：建议 2-3 周集中突击（剩余课程时间内完成）。  
> **节奏**：每个 Step = 1-3 个工作日；**严禁跨 Step 跳跃**。

### 🟢 Step 1：产品定义与 PRD 撰写（1-2 天）

**目标**：把现有 PRD 重新审视一遍，**对齐代码实现的偏差**，并补充 PPT 要求的"角色/场景/硬规则/MVP 范围"。

**AI 怎么用**（Prompt 模板化）：
1. 拿现有 `PRD.md` 给 AI：*"请基于以下 PRD，扮演资深产品经理，找出与实现可能不一致或缺失的部分"*（多轮对话）
2. *"请用 Mermaid 语法重画任务状态流转图，标注每个状态可执行的操作"*（多轮对话）
3. *"请补充 PRD 中缺失的非功能需求条目：性能、安全、可靠性、可维护性"*

**人工审查清单**：
- [ ] 三类角色权限矩阵是否完整？
- [ ] 任务状态机是否覆盖所有合法转换？
- [ ] 信用分上下限、奖励下限、服务费比例是否与代码一致？
- [ ] MVP 范围有没有遗漏/越界？

**产出物**（写进 `step1-产品定义与PRD/`）：
- `01-修订版PRD.md`（在现有 PRD 基础上修订，标注修订点）
- `02-任务状态机Mermaid.md`
- `03-AI对话记录_产品定义.md`（**关键**：记录人机协作过程）

### 🟢 Step 2：UI/UX 高保真原型设计（1-2 天）

**目标**：用 UI 反推业务逻辑，**对照现有前端代码审查"哪些页面是 AI 设计的、哪些是临时拼的"**。

**AI 怎么用**：
1. 拿 PRD 给 AI：*"请基于此 PRD，为校园众包平台设计 5 个核心页面的高保真 HTML 原型（登录页、任务大厅、任务详情、发布任务、个人中心），使用 Tailwind CSS，风格偏年轻/校园"*
2. *"请把上述原型拆分为 Vue 3 单文件组件，保留 Tailwind 类名"*

**人工审查清单**：
- [ ] 配色方案是否符合校园场景？
- [ ] 关键操作按钮（接单/提交/验收）位置是否显眼？
- [ ] 移动端响应式是否有考虑？
- [ ] 与现有 `src/views/*.vue` 视觉差异有多大？差异点是否有合理解释？

**产出物**（写进 `step2-UI-UX高保真原型/`）：
- `01-页面清单与设计说明.md`
- `02-高保真原型代码片段/`（如登录页 HTML、任务大厅 HTML）
- `03-关键界面截图/`（标注哪些是最终代码、哪些是原型）
- `04-AI对话记录_UI设计.md`

### 🟢 Step 3：API 接口契约设计（2-3 天）

**目标**：把现有 42KB `API接口文档.md` 改造成**符合 OpenAPI 3.0 规范的 Swagger 文档**，并落地到 Spring Boot（`springdoc-openapi` 依赖）。

**AI 怎么用**：
1. *"请根据以下 Controller 列表，生成对应的 OpenAPI 3.0 YAML 文件"*（喂 6 个 Controller 的源码）
2. *"请指出哪些 Controller 与 PRD 中的接口契约不一致（路径/方法/参数/响应）"*
3. *"请设计一套全局错误码规范，覆盖 4xx/5xx/业务错误码"*

**人工审查清单**：
- [ ] 所有 Controller 的真实路径与契约是否一致？（如 `/api/tasks/{id}/accept`）
- [ ] 状态码是否齐全？特别是抢单冲突的 409？
- [ ] Swagger UI 是否能正确渲染？
- [ ] 字段命名是否统一 camelCase？

**产出物**（写进 `step3-API接口契约设计/`）：
- `01-OpenAPI契约.yaml`（机器可读）
- `02-修订版API接口文档.md`（与原 API 接口文档差异对比）
- `03-Swagger落地说明.md`（包含启动后访问 URL、截图）
- `04-Controller与契约差异审计表.md`
- `05-AI对话记录_API设计.md`

### 🟢 Step 4：技术选型与系统架构（1-2 天）

**目标**：写一份**"为什么选这个技术栈"的选型对比表**，体现"经过思考"而不是"AI 说什么就用什么"。

**人工审查清单**：
- [ ] 技术栈是否与团队 2-3 人规模匹配？（没有过度设计？）
- [ ] 是否有 Redis 等中间件引入了但没用到？
- [ ] 分层是否清晰？前端是否区分了组件/页面/状态？

**产出物**（写进 `step4-技术选型与系统架构/`）：
- `01-技术选型对比表.md`（含 AI 建议 + 人工决策）
- `02-系统架构图_Mermaid.md`
- `03-项目目录结构说明.md`
- `04-AI对话记录_架构设计.md`

### 🟢 Step 5：数据架构与存储建模（2 天）

**目标**：把现有 `schema.sql` 严格审查一遍，**对照 PRD 业务规则找出 DDL 的漏洞**。

**AI 怎么用**：
1. *"请基于以下 PRD 和现有 schema.sql，找出 DDL 中的设计漏洞（缺索引、缺约束、字段类型不当、缺审计字段）"*
2. *"请画出 ER 关系图（Mermaid erDiagram 语法）"*
3. *"请为抢单场景设计乐观锁方案，给出 SQL 层面的版本号使用"*

**人工审查清单**：
- [ ] 所有外键是否正确建立？
- [ ] 涉及金额的字段是否都是 DECIMAL(10,2)？
- [ ] 审计字段（create_time/update_time/deleted）是否齐全？
- [ ] `task` 表的 `version` 字段是否真的被乐观锁使用？代码里有没有 `WHERE version = ?`？

**产出物**（写进 `step5-数据架构与存储建模/`）：
- `01-ER关系图.md`（Mermaid erDiagram）
- `02-修订版schema.sql`（含修改说明）
- `03-数据建模审计报告.md`（AI 找到的问题 + 人工修复方案）
- `04-AI对话记录_数据建模.md`

### 🟢 Step 6：前端工程化与 Mock 开发（2-3 天）

**目标**：编写一份**前端编码规范 SPEC**，并审视现有 `mock/index.js` 是否与真接口一致。

**AI 怎么用**：
1. *"请为 Vue 3 + Vite + Pinia + Tailwind 项目编写一份前端编码规范"*（喂现有代码作为参照）
2. *"请对比以下 mock 接口路径与真接口路径（来自 Step 3 的 OpenAPI），列出不一致项"*
3. *"请为我们的项目设计 API 请求的 Axios 拦截器模板（统一错误处理、Token 注入、loading 状态）"*

**人工审查清单**：
- [ ] 编码规范是否被现有代码遵守？差距有多大？
- [ ] mock 数据与真接口命名/字段是否一致？
- [ ] Vite 代理配置是否正确（`/api -> 127.0.0.1:8080`）？
- [ ] `main.js` 中的 mock 门控逻辑（`VITE_USE_MOCK`）是否稳妥？

**产出物**（写进 `step6-前端工程化与Mock开发/`）：
- `01-前端编码规范SPEC.md`
- `02-Mock与真接口差异审计表.md`
- `03-Axios拦截器设计说明.md`
- `04-AI对话记录_前端开发.md`

### 🟢 Step 7：后端业务逻辑实现（3-4 天）

**目标**：补齐 Swagger 落地，补充冒烟测试，**对核心业务逻辑做并发安全性审查**。

**AI 怎么用**：
1. *"请为本项目添加 springdoc-openapi 依赖，生成 Swagger UI 配置类，标注所有 Controller 的 @Operation 注解"*
2. *"请为以下 5 个核心场景编写 JUnit 5 单元测试：发布任务、接单（并发抢单）、提交凭证、确认完成、发起争议"*（要求模拟 10 个用户并发抢单）
3. *"请审查以下抢单 SQL 是否存在并发安全问题"*（贴出 service 代码）

**人工审查清单**：
- [ ] `@Transactional` 注解是否覆盖了所有资金操作？
- [ ] 抢单是否真的用了乐观锁（version 字段）？还是只是 if 状态判断？
- [ ] WebSocket 推送失败时，DB 通知是否仍然落库？（推送失败不应丢消息）
- [ ] Swagger UI 是否能正确登录后访问所有受保护接口？

**产出物**（写进 `step7-后端业务逻辑实现/`）：
- `01-后端编码规范SPEC.md`
- `02-核心业务单元测试代码/`（JUnit 5）

- `04-Swagger集成说明.md`
