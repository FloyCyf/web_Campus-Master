# Step 8 · 演示视频脚本

> **Step 目标**：制作 ≤ 5 分钟的演示视频，覆盖 P0 关键业务步骤。  
> **验收要求**："演示视频片段（不超过 5 分钟，关键业务步骤的录屏即可）"  
> **录制工具**：Windows 自带录屏（Win+G）或 OBS Studio

---

## 一、视频结构（总时长 ≤ 5 分钟）

| 段 | 内容 | 时长 | 重点 |
|---|------|------|------|
| 1 | 开场：项目介绍（30 秒） | 0:00-0:30 | 一句话定位 + 演示账号 |
| 2 | 需求方发任务 | 0:30-1:20 | 表单填写 + 资金冻结 |
| 3 | 接单方接单 | 1:20-2:00 | 状态变化 + 通知 |
| 4 | 提交凭证 + 验收 | 2:00-3:00 | 资金结算 |
| 5 | 双向评价 | 3:00-3:40 | 信用分更新 |
| 6 | 管理员后台 | 3:40-4:20 | 数据统计 + 争议处理 |
| 7 | 收尾 | 4:20-5:00 | 关键亮点 + 致谢 |

---

## 二、分段脚本

### 2.1 开场（0:00-0:30）

**画面**：项目首页（任务大厅）

**旁白**：
> 大家好，我们组开发的"校园万事达"互助众包任务平台。系统支持学生发布互助需求（如取快递、代买餐），其他学生接单赚取报酬，平台通过资金担保和信用评分保证交易安全。
> 
> 下面我演示完整流程。三个测试账号分别是：需求方张小明、接单方李小红、管理员。

**操作**：
- 0:00-0:10 显示项目首页
- 0:10-0:20 切换到登录页
- 0:20-0:30 依次输入 3 个账号（仅显示，不操作）

---

### 2.2 需求方发任务（0:30-1:20）

**画面**：登录需求方 → 进入发布任务页

**旁白**：
> 需求方登录后，进入发布任务页面。填写任务标题、分类、描述、报酬（10 元），系统自动计算 5% 服务费。
> 
> 点击发布后，资金从可用余额转入冻结。任务出现在任务大厅。

**操作**：
- 0:30-0:40 登录需求方 `13800000001 / 123456`
- 0:40-0:50 跳转到 `/publish`
- 0:50-1:00 填写任务（标题"帮取快递"、分类"跑腿代取"、描述、报酬 10、截止时间明天）
- 1:00-1:10 点击发布 → 跳转到 `/my-tasks`，看到任务状态"待接单"
- 1:10-1:20 跳转到 `/profile` 看到余额从 500 → 489.5（冻结 10 元 + 0.5 服务费？注：实际不冻结服务费）

> 💡 **旁白补正**：本期服务费不在发布时预扣，所以余额变成 490（-10），冻结 10 元。

---

### 2.3 接单方接单（1:20-2:00）

**画面**：切换到接单方 → 浏览任务 → 详情 → 接单

**旁白**：
> 切换到接单方账号。进入任务大厅，看到刚发布的需求。点击"立即接单"，任务状态变为"进行中"。
> 
> 需求方会实时收到通知（WebSocket 推送）。

**操作**：
- 1:20-1:30 退出登录，用接单方 `13800000003 / 123456` 登录
- 1:30-1:40 进入 `/home`，看到任务列表
- 1:40-1:50 点击任务卡 → 进入详情
- 1:50-2:00 点击"立即接单" → 跳 `/my-tasks`，状态变"进行中"

---

### 2.4 提交凭证 + 验收（2:00-3:00）

**画面**：接单方提交 → 需求方验收

**旁白**：
> 接单方在"我的任务"中找到进行中的任务，点击"提交完成"，输入文字凭证。任务状态变为"待验收"。
> 
> 切换回需求方账号，验收任务。资金从冻结转入接单方账户（5% 服务费由接单方承担）。

**操作**：
- 2:00-2:15 接单方 `/my-tasks` → 点击"提交完成" → 跳 `/submit/:id` → 输入文字 → 提交
- 2:15-2:30 状态变"待验收"
- 2:30-2:40 切换到需求方账号
- 2:40-2:50 需求方 `/my-tasks` → 点击"去验收" → 跳 `/review/:id` → 点击"确认完成"
- 2:50-3:00 状态变"已完成"，资金自动结算

---

### 2.5 双向评价（3:00-3:40）

**画面**：双方互评

**旁白**：
> 任务完成后，双方可以互评。需求方给接单方 5 星好评（+2 信用分），接单方给需求方 4 星好评（+1 信用分）。
> 
> 信用分实时更新。

**操作**：
- 3:00-3:10 需求方进入 `/my-tasks` → 点击"评价对方" → 跳 `/rate/:id` → 选 5 星 + 写"服务很好" → 提交
- 3:10-3:20 切换到接单方 → 同样路径评价 4 星
- 3:20-3:30 双方进入 `/profile` → 看到信用分更新
- 3:30-3:40 切到通知中心 → 看到"收到新评价"通知

---

### 2.6 管理员后台（3:40-4:20）

**画面**：登录管理员 → 后台

**旁白**：
> 管理员登录后，看到平台监控数据：用户数、任务数、交易额。
> 
> 我们这里发起一个新的争议来演示管理员处理流程。

**操作**：
- 3:40-3:50 退出登录，用管理员 `13800000000 / Admin123` 登录
- 3:50-4:00 进入 `/admin` → 看到 4 个 tab
- 4:00-4:10 切到"平台监控" → 看到 4 个数据卡 + 进度条
- 4:10-4:20 切到"用户申诉处理" → （如有争议）点击"支持接单方"处理

---

### 2.7 收尾（4:20-5:00）

**画面**：回到任务大厅

**旁白**：
> 我们用 5 分钟演示了核心流程：发布 → 接单 → 提交 → 验收 → 评价 → 管理员处理。
> 
> 系统通过资金冻结 + 信用评分 + 状态机保证了交易安全和流程严谨。代码约 5000 行，包含 8 张表、6 个 Controller、11 个 View。
> 
> 我们的亮点是：**严格的 RBAC 权限隔离**、**事务一致性的资金流转**、**乐观锁防并发抢单**。
> 
> 谢谢各位老师！

**操作**：
- 4:20-4:40 切回 `/home` 显示任务列表
- 4:40-5:00 显示项目 Logo 或团队合影

## 三、录制注意事项

| 项 | 建议 |
|------|------|
| 浏览器 | Chrome 全屏（1080p） |
| 后端日志 | 提前关掉 INFO 级日志（避免泄露） |
| 鼠标移动 | 不要太快，停顿 1-2 秒 |
| 旁白 | 用文字稿录制，**不要临场发挥**（避免口误） |
| 错误处理 | 如果演示中出错，**不要慌**——重录 |
| 视频格式 | MP4，H.264，分辨率 1080p |
| 文件大小 | 控制在 200MB 以内 |

## 四、备用 Plan B

> 📌 **如果演示视频录制失败或时间不够**，Plan B 是：

### 4.1 用截图代替视频

- 关键步骤截图（每步 1-2 张）
- 用 PPT 拼接成"伪视频"
- 配文字说明
- 转 PDF

### 4.2 录屏工具替代

- **Windows**：Win+G（Xbox Game Bar）
- **Mac**：QuickTime / Cmd+Shift+5
- **专业**：OBS Studio（推荐，免费开源）
- **浏览器插件**：Loom / Screencastify

### 4.3 演示数据准备

> 📌 **演示前**用 5 分钟准备：

```sql
-- 清空所有业务数据
DELETE FROM task_log;
DELETE FROM review;
DELETE FROM dispute;
DELETE FROM notification;
DELETE FROM transaction;
UPDATE account SET balance=500, frozen_balance=0 WHERE user_id=2;
UPDATE account SET balance=200, frozen_balance=0 WHERE user_id=3;
UPDATE account SET balance=1000, frozen_balance=0 WHERE user_id=1;

```

**重要**：演示账号的初始余额/状态要**恢复到干净状态**。

## 五、5 分钟视频的"取舍"

> 📌 **5 分钟内能演示什么 / 不能演示什么**：

| 能演示 | 不能演示（v2） |
|--------|--------------|
| 核心任务流（发→接→提→验→评） | 提现功能（未做） |
| 双向评价 + 信用分更新 | 校园身份认证（未做） |
| 管理员统计 + 争议处理 | 团队组队（未做） |
| 取消任务 | IM 即时通讯（未做） |
| 权限校验 | GeoHash（未做） |
| 并发抢单（10 线程）| AI 审核（未做） |
| Swagger UI | Docker 部署 |

**原则**：**5 分钟只演示"做得好的"，不演示"没做的"**。

| 场景 | 操作 |
|------|------|
