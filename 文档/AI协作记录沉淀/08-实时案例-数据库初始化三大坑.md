## 二、三个坑的完整故事

### 坑 1：PowerShell 不支持 `<` 输入重定向

**场景**：
按文档指示运行：
```powershell
mysql -u root -pCyf200592 campus_master < src\main\resources\schema.sql
```

**报错**：
```
“<”运算符是为将来使用而保留的。
+ CategoryInfo : ParserError: (:) [], ParentContainsErrorRecordException
```

**根因**：
- Bash 和 CMD 都支持 `<` 重定向
- **PowerShell 不支持**——它有自己的 `Get-Content` 管道
- 这是 PowerShell 5.1 的设计选择

**修复**：
```powershell
# PowerShell 方式
Get-Content src\main\resources\schema.sql | mysql -u root -pCyf200592 campus_master
```

**为什么 AI 没主动说**：
- AI 假设所有命令行都是 Bash/CMD 环境
- AI 不区分"用户在哪个 Shell"
- **AI 对"运行环境"不敏感**——这是个"部署"领域知识

> 💡 **教训**：**跨平台文档必须写"在 PowerShell 用什么命令"**——AI 给的"标准 Linux 教程"在 Windows PowerShell 上是错的。

### 坑 2：MySQL 客户端默认 GBK 编码，导入 UTF-8 数据失败

**场景**：
用 `Get-Content` 导入 data.sql 时，**第一条 INSERT 失败**：
```
ERROR 1366 (HY000) at line 6: Incorrect string value: '\x80...' for column 'username' at row 1
```

**根因**：
- MySQL **客户端**默认用操作系统的字符集（Windows 中文系统 = GBK）
- 但服务端和表都是 `utf8mb4`
- **客户端 → 服务端**的传输编码 = GBK，但服务端的"需求方"等中文字符在 GBK 中无法表达
- `0x80` 在 GBK 中是无效字符

**修复**：
```bash
mysql -u root -pCyf200592 --default-character-set=utf8mb4 campus_master
```

**为什么 AI 没主动说**：
- AI 给的"mysql 标准用法"通常假设服务器端和客户端都是 utf8mb4
- AI **不知道你的 Windows 系统语言**是中文
- 跨平台开发的标准"隐藏配置"——AI 不会主动提

> 💡 **教训**：**MySQL 命令行必须显式指定 `--default-character-set=utf8mb4`**——这是"中文 Windows + MySQL"的标准配置。

### 坑 3：schema.sql 开头有 UTF-8 BOM

**场景**：
导入 schema.sql 时，**第一条 CREATE TABLE 失败**：
```
ERROR 1064 (42000) at line 1: You have an error in your SQL syntax...
near '?????,
    `password` VARCHAR(255) NOT NULL COMMENT '???',
```

**根因**：
- schema.sql 是**用某个编辑器（如 VSCode / Windows 记事本）保存的**
- 开头有 3 字节的 UTF-8 BOM：`\xef\xbb\xbf`
- MySQL 看到 BOM 当成 SQL 内容的一部分——`?????` 是 3 个不可见字符

**修复**：
需要先去掉 BOM 再导入：
```python
# Python 方式
with open('schema.sql', 'rb') as f:
    content = f.read()
if content.startswith(b'\xef\xbb\xbf'):
    content = content[3:]
# 然后用 content 作为 stdin 喂给 mysql
```

**为什么 AI 没主动说**：
- AI 看不到**文件本身的字节**
- AI 只看"代码逻辑"——不会主动扫描"文件格式"
- 这是**编辑器生成的隐藏问题**——AI 不会想到

> 💡 **教训**：**永远不要相信"文件是干净的"——导入前先 hexdump 看前几字节**。

## 三、3 个坑的"通用方法论"

> 📌 **这 3 个坑都体现一个共同主题**：**AI 对"部署/运维"领域不敏感**。

| 坑 | 类别 | AI 没主动说的原因 |
|---|------|------------------|
| 坑 1 PowerShell | Shell 差异 | AI 假设 Bash 环境 |
| 坑 2 GBK | 字符集 | AI 不知道 Windows 区域 |
| 坑 3 BOM | 文件格式 | AI 看不到文件字节 |

**通用方法论**：
> "AI 给你代码时，**假设它不知道你的部署环境**。在 cmd / PowerShell / Linux / 中文 Windows / Mac 都要分别验证一遍。"

## 七、附录：完整的"修复版"导入命令

```bash
# 一次性脚本（推荐保存到 reset_mysql.bat）
python -c "
import subprocess, sys
sys.stdout.reconfigure(encoding='utf-8')

def import_sql(path):
    with open(path, 'rb') as f:
        content = f.read()
    if content.startswith(b'\xef\xbb\xbf'):
        content = content[3:]
    result = subprocess.run(
        ['mysql', '-u', 'root', '-pCyf200592', '--default-character-set=utf8mb4', 'campus_master'],
        input=content, capture_output=True
    )
    if result.returncode != 0:
        print(f'[FAIL] {path}')
        print(result.stderr.decode('utf-8', errors='replace'))
    else:
        print(f'[OK] {path}')

# 1. 重建库
subprocess.run(['mysql', '-u', 'root', '-pCyf200592', '-e',
    'DROP DATABASE IF EXISTS campus_master; CREATE DATABASE campus_master DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;'])
print('[OK] Database recreated')

# 2. 导入
import_sql('src/main/resources/schema.sql')
import_sql('src/main/resources/data.sql')
"
```

> 📌 **这个脚本本身**就可以作为 `reset_mysql.bat` 保存到项目根目录——**未来任何开发者都能用**。
